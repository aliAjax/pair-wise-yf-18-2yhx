# 宝石刻面返工迁移台

React + Vite + TypeScript 单页应用。改单尺寸后，把原订单的已分拣宝石逐颗迁往最早的缺品订单。

## 业务文件

- `src/rules.ts` — 类型、五张改单与十六颗宝石预置数据、缺品判定与迁移引擎
- `src/storage.ts` — localStorage 存档（刷新保留，损坏时回退预置数据）
- `src/page.tsx` — 迁移台页面（改单卡片 / 宝石清单 / 迁移台账）
- `src/App.tsx` — 入口，仅装配上面三个文件

## 迁移规则

1. 改单修改主石目标尺寸后，从原订单逐颗释放宝石。
2. 迁往**最早的缺品订单**（下单日期升序），候选石位须外形、主/配角色一致。
3. **优先尺寸差最小**（Δ 升序，平局按最早订单 → 单号 → 主石位 → 宝石编号）。
4. 尺寸差 **> 0.15mm** 或**缺陷未复核**的宝石留在原点并计入待处理（软留，不阻断其他宝石）。
5. 出现**占用冲突**（尺寸内配石位已满）或**主石超额**（主石位已有主石）时，合格宝石无位可去，**整次不迁**：尺寸改单保留，全部宝石回滚。

## 本地运行

```bash
npm install
npm run dev        # 开发服务器 http://localhost:62006
npm run build      # 生产构建 + tsc 类型检查
npm test           # 规则引擎语义断言（scripts/test-rules.ts）
```

## 预置数据一览

- 5 张改单 GD-301 … GD-305，GD-305 为返工源单；
- 16 颗宝石 S-01 … S-16，记录外形、毫米尺寸、缺陷复核状态与主/配石位；
- 默认对 GD-305 改单 9.5 → 8.0：S-10 主石与 S-13/S-12 配石迁往 GD-301；S-15（Δ0.20）尺寸超限、S-11/S-14 未复核，留原点待处理；
- 在清单中点「待复核」复核 S-14 后再改单 → 占用冲突整次不迁；复核 S-11 → 主石超额整次不迁。
